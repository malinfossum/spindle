# Spindle v0.5 — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A scan looks the barcode up on its own, a picked match brings its front cover from the Cover Art Archive, the look-ups question is asked once after Create library, an opt-in checkbox keeps the device unlocked across reloads, and two router bugs from the phone are fixed.

**Architecture:** No new layer. The lookup Controller (`Controller/Edit_Music_Details/lookup.js`) gains one shared path, `runLookup(digits)`, that both the button and the scanner call; the MusicBrainz Model (`Model/musicbrainz.js`) gains `fetchCover()` and stays the only file that knows a host. The IndexedDB open/transaction helpers move out of `Model/covers.js` into a new `Model/db.js` so the new `session` store in `Model/auth.js` shares them instead of copying them. The stored key is read once at boot by `restoreSession()` in `Controller/Login/login.js`, through the same `unlockWith()` the password path uses. Everything else is a field added where its shape already lives: `blankLookup()`, `PREFS_DEFAULTS`, the login form state, `model.app`, the two string tables, `_headers`.

**Tech Stack:** Vanilla JS modules, Vite 8 dev server, Biome, Node 26 `node --test` for the pure Model pieces, the browser pane for everything else. No new dependency.

**Spec:** `docs/v0.5-plan.md` — every task below cites the section it implements. Read the spec first; the plan argues from it.

## Global Constraints

- MVC: Model has no DOM and no timers; View renders and forwards `data-action`; Controller does the rest. This is why the blob sniff and the downscale of a fetched cover happen in the Controller, not in `Model/musicbrainz.js` — `sniff.js` and `downscale.js` are View helpers and the Model does not import from the View.
- Shapes are defined once: `blankLookup()` in `Model/model.js`, `blankAlbum()` there too. Nothing new goes on the album in v0.5 (spec § 3 "Data"), so `normalizeAlbums()` is not touched.
- Every template escapes with `escapeHtml()`; `t()` does not escape its parameters, so escape before passing.
- Hosts: `https://musicbrainz.org`, `https://coverartarchive.org`, `https://archive.org`, `https://*.archive.org` — exactly these four in `connect-src`, measured by the probe in Task 1 (2026-09-22: `coverartarchive.org` 307 → `archive.org/download/…` 302 → `dn721803.ca.archive.org/…` 200; all three hops send `Access-Control-Allow-Origin: *`). `img-src` does not change.
- Nothing is sent until `getPref("lookups") === "on"`. That value is set only by a consent dialog resolving yes (the v0.4 press dialog, or the new Create-library question) or by the Profile select. Nothing is requested from the archive unless a MusicBrainz request has already been agreed to.
- The session store holds one non-extractable AES-GCM `CryptoKey` and nothing else: never the verify key, the salt, the username or the password. `stayUnlocked` is mirrored on `model.app` because views render synchronously and IndexedDB does not.
- Every way a step can fail gets its own visible message, in both languages (spec § 0, standing rule). A spinner that stops is not a message.
- Commit subjects are plain sentence case, no conventional-commit prefix, no attribution trailer. Biome formats with tabs, double quotes, line width 100 — run `npm run check` before each commit. Every commit goes to the branch `v0.5`; `main` is landed by a PR Malin merges.
- Strings: every new key exists in both `Model/i18n/en.js` and `Model/i18n/no.js`, in the same commit. The NO drafts are mine to read before v0.5 ships.
- Node tests live in `test/*.test.js` and import only Model files with no `window`, `document` or `indexedDB` at module scope: `model.js`, `musicbrainz.js`, `selectors.js`, and — new this round — `prefs.js`, which touches `localStorage` only inside function bodies. `auth.js`, `covers.js` and `db.js` are verified in the pane.
- Pane traps (spec § 9): restart the dev server before driving state from `javascript_tool` (HMR splits the module graph); a hidden pane never fires `<dialog>` `close` — screenshot first; open a fresh tab before judging the console; `127.0.0.1:5070` and `localhost:5070` are two origins with separate storage.
- Before building any task, `git log -S "<its main symbol>"` — a "not built" item may be half there.

## What the code says the spec did not know

Read before Task 1; each is settled here so no task has to re-decide it.

- **There is no change-password and no delete-library feature** (`grep -rn "changePassword\|newPassword"` over `Controller Model View` is empty; `Controller/Universal/delete.js` deletes albums only). Spec § 5 lists both as clearing paths. The real paths are: `logout()`, restore backup (`importBackupFile()` calls `logout()`), and the Profile toggle set to off. Task 9 wires those three and leaves a one-line comment at `clearSessionKey()` naming the two that will need it if they are ever built.
- **The lookup timeout is 10 s** (`LOOKUP_TIMEOUT_MS = 10_000` in `lookup.js`), not the 8 s spec § 3 says. The cover request shares the constant; the spec's number is a typo and the plan does not change it.
- **The fill sentence is `music.lookupFilled`** ("Filled from MusicBrainz: {artist} – {title}"), not "Filled title and year". The cover sentence is appended to it as the spec asks.
- **`openDialog()` resolves to a boolean**, so "No button" and "Escape" are the same value today. Task 6 adds an `outcomes` option that resolves `"confirm" | "cancel" | "dismiss"` and leaves every existing caller on the boolean.
- **The burger button carries no `aria-expanded`** (`index.html:89`). Spec § 1 says `closeMobileMenu()` sets it "when it carries the attribute". Task 2 adds the attribute to the button and keeps it in step in both directions, so the class and the state say the same thing rather than the attribute being dead code.
- **A `<select>` with two options cannot show "unset"**: the first option renders selected, and re-choosing it fires no `change`, so a person could never pick "off" from "unset". Task 6 adds a disabled placeholder option, selected only while the pref is `unset`. The two choosable options stay off / on, as spec § 4 says.
- **`model.app.authMessage` renders on Login and Register only.** Spec § 5 wants "Logged in, but this device could not be kept unlocked" after a login that lands on Home, and the Profile toggle needs a failure line too. Task 9 extracts the three-line paragraph both auth views already carry into `View/Universal/authNotice.js` and renders it on Home, Profile and Welcome as well. Three keys beyond spec § 6 come from the standing rule: `profile.stayFailed`, `profile.stayClearFailed`, `login.stayClearFailed` — a clear that fails leaves the device unlocked, which is the one failure that must never be silent.
- **`scanPressed()` blanks the lookup state on every scan** (`barcodeTyped()` replaces `form.lookup`), which would blank `lookup.owned` and make a second scan of the same sleeve stop again instead of sending. Task 7 skips the re-type when the field already holds the same digits.
- **`Model/covers.js` imports `Model/auth.js`**, so putting the session store in `auth.js` and importing `openDb` from `covers.js` would be an import cycle. Task 8 moves the open/transaction helpers to `Model/db.js`; both files import from there.

In `Model/prefs.js`, replace lines 13–27 with:

```js
// Bumped when a stored value has to be read differently (v0.5). A blob
// without the field is v0.4's and goes through migratePrefs() once.
const PREFS_VERSION = 2;

const PREFS_DEFAULTS = {
	lang: "no",
	theme: "dark",
	// v0.4, widened in v0.5. Whether a barcode may be sent to musicbrainz.org
	// and a cover fetched from coverartarchive.org. "unset" until the question
	// has been answered — once after Create library, or on the first Look up;
	// "off" is an answer and is never asked again. Plaintext on purpose: it has
	// to be readable before unlock, and it says nothing about what the library
	// holds.
	lookups: "unset",
};

const PREFS_ALLOWED = {
	lang: ["no", "en"],
	theme: ["dark", "light"],
	lookups: ["unset", "off", "on"],
};

// Brings a v0.4 blob up to v2, in place. The v0.4 yes was given for one host
// and v0.5 sends to two, so it goes back to unset and the dialog — naming both
// hosts — asks once more. An off was a deliberate choice and still means no.
function migratePrefs(parsed) {
	if (parsed.prefsVersion === PREFS_VERSION) return false;
	if (parsed.lookups === "on") parsed.lookups = "unset";
	return true;
}
```

In `readPrefs()`, replace the `for` loop and the `return` after it (lines 61–67) with:

```js
	const migrated = migratePrefs(parsed);

	// Whitelist every value on the way in. A hand-edited or corrupted blob must
	// not be able to put the app into a state the UI has no rendering for.
	for (const name of Object.keys(PREFS_DEFAULTS)) {
		if (PREFS_ALLOWED[name].includes(parsed[name])) {
			prefsCache[name] = parsed[name];
		}
	}

	// Written back once so the migration does not run on every read — and so
	// a blob that never carried a version carries one from now on.
	if (migrated) writePrefs(prefsCache);

	return prefsCache;
```

Add `writePrefs()` above `invalidatePrefsCache()` and make `setPref()` use it (replace lines 82–95):

```js
function writePrefs(prefs) {
	try {
		localStorage.setItem(PREFS_KEY, JSON.stringify({ prefsVersion: PREFS_VERSION, ...prefs }));
	} catch (err) {
		// Quota or disabled storage. The in-memory cache is already updated, so
		// the preference still applies for this session.
		console.warn("[prefs] could not persist preferences:", err);
	}
}

export function setPref(name, value) {
	if (!PREFS_ALLOWED[name]?.includes(value)) return;

	const prefs = readPrefs();
	prefs[name] = value;
	writePrefs(prefs);
}
```

```js
// The front cover of a release group, as a blob, or why there is none. The
// caller sniffs the bytes and decodes them: this file has no DOM and does not
// import the View's image helpers. A rejection is fetch's own — aborted,
// timed out, offline — and is left to the caller, as lookupBarcode() does.
export async function fetchCover(releaseGroupId, signal) {
	if (!isReleaseGroupId(releaseGroupId)) return { status: "none" };

	const response = await fetch(COVER_URL(releaseGroupId), { signal });

	if (response.status === 404) return { status: "none" };
	if (response.status === 503 || response.status === 429) return { status: "busy" };
	if (!response.ok) return { status: "failed" };

	// front-500 is a request, not a guarantee. The header is checked so an
	// oversized file is not downloaded; the blob is checked because the header
	// can be absent or wrong across a redirect.
	const declared = Number(response.headers.get("content-length"));
	if (declared > COVER_MAX_BYTES) return { status: "failed" };

	const blob = await response.blob();
	if (blob.size > COVER_MAX_BYTES) return { status: "failed" };

	return { status: "ok", blob };
}
```

```js
// The one IndexedDB database, "spindle", and the helpers every store in it
// uses. They lived in covers.js while covers were the only store; the session
// key (v0.5) is the second, and auth.js cannot import them from covers.js —
// covers.js imports auth.js for the cipher, and that would be a cycle.
//
//   covers  — { id: "<uuid>", iv: Uint8Array(12), data: Uint8Array }, sealed
//             with the library key (see covers.js)
//   session — { id: "session", key: CryptoKey }, the non-extractable AES-GCM
//             key itself, kept only when "Stay unlocked" was ticked (see auth.js)

const DB_NAME = "spindle";
// 2 (v0.5) adds the session store. onupgradeneeded creates whichever store is
// missing, so a database at either version ends up with both.
const DB_VERSION = 2;
export const COVERS_STORE = "covers";
export const SESSION_STORE = "session";

let dbPromise = null;

export function openDb() {
	if (dbPromise) return dbPromise;

	dbPromise = new Promise((resolve, reject) => {
		const request = indexedDB.open(DB_NAME, DB_VERSION);

		request.onupgradeneeded = () => {
			const db = request.result;
			for (const name of [COVERS_STORE, SESSION_STORE]) {
				if (!db.objectStoreNames.contains(name)) db.createObjectStore(name, { keyPath: "id" });
			}
		};

		request.onsuccess = () => {
			const db = request.result;
			// A newer build in another tab wants to upgrade: let go of this
			// connection so it can, and reopen lazily. A v0.4 tab never did this,
			// so the first upgrade to 2 waits for such a tab to close or reload.
			db.onversionchange = () => {
				db.close();
				dbPromise = null;
			};
			resolve(db);
		};
		request.onerror = () => reject(request.error);
		request.onblocked = () => reject(new Error("IndexedDB upgrade blocked by another tab"));
	}).catch((err) => {
		// A failed open must not be cached as a permanent no: private-mode and
		// storage-blocked failures can clear between attempts.
		dbPromise = null;
		throw err;
	});

	return dbPromise;
}

// One place that turns a request into a promise, so no call site writes its own
// onsuccess/onerror pair.
export function run(store, work) {
	return new Promise((resolve, reject) => {
		const request = work(store);
		request.onsuccess = () => resolve(request.result);
		request.onerror = () => reject(request.error);
	});
}

export async function withStore(storeName, mode, work) {
	const db = await openDb();
	const tx = db.transaction(storeName, mode);
	const result = await work(tx.objectStore(storeName));

	// Resolve on the transaction, not on the request: a write is not durable
	// until its transaction commits, and reporting success before then would let
	// the app navigate away from a save that has not landed.
	await new Promise((resolve, reject) => {
		tx.oncomplete = () => resolve();
		tx.onerror = () => reject(tx.error);
		tx.onabort = () => reject(tx.error ?? new Error("IndexedDB transaction aborted"));
	});

	return result;
}
```

```js
// Boot (v0.5): a key kept by "Stay unlocked on this device" opens the library
// before the first route renders, through the same unlockWith() the password
// path uses. A missing key is the normal case and is silent. A key that does
// not open the envelope — a backup restored from another device, a corrupt
// store — is cleared, and the Login page says so; nothing is thrown either way.
export async function restoreSession() {
	let key;
	try {
		key = await readSessionKey();
	} catch (err) {
		console.warn("[session] could not read the store:", err);
		return "none";
	}
	if (!key) return "none";

	const result = readEnvelope();
	if (!result?.ok) {
		// The library is gone or unreadable; a key to nothing is cleared quietly.
		await clearSessionKey().catch(() => {});
		return "none";
	}

	try {
		await unlockWith(key, result.envelope);
	} catch (err) {
		console.warn("[session] stored key rejected:", err);
		zeroKeys();
		await clearSessionKey().catch(() => {});
		model.app.sessionStale = true;
		return "stale";
	}

	model.app.stayUnlocked = true;
	return "restored";
}
```
