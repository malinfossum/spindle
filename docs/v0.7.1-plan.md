**Goal:** v0.7 is tidied up. Removing a genre or a location no longer relabels my albums, long genres stay inside their card, and the loose ends from the v0.7 review are closed.

**Architecture:** No new module. The removal fix is one Model function beside `blankAlbum()` in `Model/model.js`, tested in Node. ## What and why

| # | Item | Why |
|---|------|-----|
| 1 | Removing a genre or location shifts every later one on every album | Albums store positions in `model.data.genre` and `model.data.location`, and `splice()` moves every later position down one. An album tagged with a later genre silently shows the next one along; the last one shows `undefined`. The library filter holds a position too. |
| 2 | Genre chips overflow under View and Delete on the home card | `.tag` is `white-space: nowrap`, and all of an album's genres share one tag. "Hip hop, Hardcore hip hop, Horrorcore" on The Slim Shady LP runs under Delete on my phone. |
| 3 | Wheel zoom is 10 % per event, whatever the event | A trackpad sends many small wheel events, so the zoom races the range. |
| 4 | Dragging on the crop stage can select text | `.crop-stage` has no `user-select: none`. |
| 5 | A hand-typed "Hip hop" is added beside my "Hip-hop" | `newGenre()` compares with `toLowerCase()`, not `genreKey()`. |
| 6 | The caret jumps when the look-up re-renders the form | `settleCover()` and `addGenres()` put focus back, but not the caret, so typing in Notes while the cover arrives lands at the wrong place. |
| 7 | `fill()` leaks its controller if a step throws | The release after `Promise.all` is skipped on a rejection. The one real throw is `sniffImageType()` reading the blob, and it also leaves an unhandled rejection and a cover line that never settles. |
| 8 | A failed look-up after a fill keeps the old genre names on the model | `runLookup()` resets `filled`, `cover` and `matches`, not `genres`. The line is hidden only because it renders inside the filled line, which `filled = null` hides. |
| 9 | Genre tests are missing four cases | The 0.25 boundary, an astral character cut at 40, the signal reaching `fetch`, and a rejection propagating. |

## Global Constraints

- MVC: Model has no DOM and no timers. View renders and draws. Controller handles events and the flow.
- No new dependency, no new string key, no CSP change.
- Node tests live in `test/*.test.js` and import only files with no `window`, `document` or `indexedDB` at module scope.
- Commit subjects are plain sentence case, no conventional-commit prefix, no attribution trailer. Run `npm run check` and `npm test` before each commit. Every commit goes to the branch `v0.7.1`; `main` is landed by a PR I merge.
- Implementer subagents run on Sonnet or better. Edit existing files with a single Edit per change, never by rewriting the file.
- Controls on one row share one height (44 px) and one bottom edge. Measure any row a task touches.
- Pane traps: resize the pane before measuring (a hidden pane lays out at 0 px); restart the dev server before driving the model from `javascript_tool` (HMR splits the module graph); open a fresh tab before judging the console; use `127.0.0.1:PORT` for a throwaway library so the `localhost` library is left alone.
- Before building any task, run `git log -S "<its main symbol>"`. As of 2026-09-30 none of these fixes exist on `main` (`aab4cba`).

- [x] **Step 3: Add `removeListEntry()` to `Model/model.js`, after `blankLibraryView()`**

```js
// Albums store positions in my genre and location lists, not names. Removing
// an entry moves every later one down a place, so everything that holds a
// position moves with it: the saved albums, the album on the form and the
// library's filter. A position on the removed entry simply goes.
export function removeListEntry(field, index) {
	// splice(-1, 1) would remove the last entry, so a position that is not
	// there removes nothing.
	if (!Number.isInteger(index) || index < 0 || index >= model.data[field].length) return;
	model.data[field].splice(index, 1);
	const shift = (positions) =>
		positions.filter((p) => p !== index).map((p) => (p > index ? p - 1 : p));

	for (const album of model.data.musicInfo) album[field] = shift(album[field]);
	model.viewState.musicInfo[field] = shift(model.viewState.musicInfo[field]);

	const filter = model.viewState.library[field];
	if (filter === "") return;
	const position = Number(filter);
	model.viewState.library[field] =
		position === index ? "" : String(position > index ? position - 1 : position);
}
```

- [x] **Step 3: Add `wheelFactor()` after `zoomBy()`**

```js
// One mouse-wheel notch is about 100 px (Chrome, Edge, Safari), 3 lines
// (Firefox) or a page. A trackpad sends many small deltas instead, so the zoom
// follows the distance rather than the number of events, and one event never
// zooms more than one notch.
export const WHEEL_NOTCH_PX = 100;

export function wheelFactor(deltaY, deltaMode = 0) {
	let notches = deltaY / WHEEL_NOTCH_PX;
	if (deltaMode === 1) notches = deltaY / 3;
	if (deltaMode === 2) notches = Math.sign(deltaY);
	return ZOOM_STEP ** -Math.max(-1, Math.min(1, notches));
}
```

- [x] **Step 1: Add the focus helpers after `focusById()`**

```js
// What has focus, and where its caret is, so a re-render can put both back.
// A number field has no caret API (selectionStart is null there), so only
// its focus returns. The genre and location boxes have no id, so they are
// found by their action and position instead; positions cannot shift before
// Save.
function focusSnapshot() {
	const node = document.activeElement;
	let selector = null;
	if (node?.id) selector = `#${node.id}`;
	else if (node?.dataset?.actionChange && node.dataset.index !== undefined) {
		selector = `[data-action-change="${node.dataset.actionChange}"][data-index="${node.dataset.index}"]`;
	}
	if (!selector) return null;
	const caret =
		typeof node.selectionStart === "number"
			? [node.selectionStart, node.selectionEnd, node.selectionDirection]
			: null;
	return { selector, caret };
}

function restoreFocus(snapshot) {
	if (!snapshot) return;
	const node = appRoot.querySelector(snapshot.selector);
	if (!node) return;
	node.focus();
	if (snapshot.caret && typeof node.setSelectionRange === "function") {
		node.setSelectionRange(...snapshot.caret);
	}
}
```

## Considered and rejected (stress test)

- **The removal dialog racing state.** The dialog closes on `hashchange`, and the list cannot change while it is modal. Ticks that land during it are shifted, because the removal runs after them.
- **Other stores of positions.** `pendingGenres` and `lookup.genres` hold names, and search history holds strings. A backup carries the list and its positions together. The edit and view paths copy the arrays.
- **`restoreFocus()` throwing.** It cannot: the caret is captured only when `selectionStart` is a number, and the same element re-renders as the same type.
- **Mouse notches below 100 px on macOS.** Accepted. The clamp only caps, and that is not my platform.
- **`max-width: 100%` on the tag** is redundant beside `white-space: normal`, but it is kept as a guard for a tag with a long single word.
