# Spindle v0.1 — plan

The original v0.1 task list lived outside the repo and was lost. This file
replaces it and lives in version control so that cannot happen again. It is the
spec of record for the rest of v0.1.

Task letters are kept from the original list so older commit messages still line
up. Letters with no entry below (L) were dropped before this file was written.

---

## Locked decisions

Settled early and not up for re-litigation without a reason:

| Area | Decision |
|---|---|
| Persistence | `localStorage`, namespaced `spindle:v1:state`, with a schema version |
| Encryption | PBKDF2 600k → HKDF → separate verify + encrypt keys, AES-GCM at rest |
| User model | No roles. One library per browser. Login is a passcode unlock, not an account |
| Multi-device | Encrypted export/import. Plaintext export is opt-in behind an explicit warning |
| Language | Norwegian and English from day one — `t()` helper, two string files, in-app toggle |
| Framing | A general-purpose music library, never "Geir's" |
| Build | Non-module scripts in v0.1. Vite migration in v0.2 |
| License | Apache-2.0, "Copyright 2026 Malin Fossum" |
| Hosting | GitHub Pages via Actions in v0.3. No `gh-pages` branch |

## Shipped

**A, B, C/C2, D, E, F, F1, G, H, I, J, K, M, N, O — all of v0.1.**

The load-bearing parts of the as-built:

- **C — auth and encryption.** Envelope shape is
  `{schemaVersion, kdfSalt, iv, verifyHmac, ciphertext}`. Keys are
  non-extractable. Register means "create library", login means "unlock", logout
  zeroes the keys. Username is display-only; there is no user table.
- **F1 — dialogs.** `openDialog(opts) → Promise<boolean>` in
  `View/Universal/dialog.js`, built on native `<dialog>` + `showModal()` for a
  real focus trap. Body is written with `textContent`, so user-entered names go
  in unescaped and safe.
- **H — welcome and about.** There is **no hash router**. Welcome and About are
  pages in the existing `changePage`/`currentPage` switch. Navbar and footer are
  hidden across the whole logged-out flow via `body.chrome-hidden`.
- **I + M — bilingual and prefs.** See "Conventions" below.
- **J — backup and restore.** A backup file is a thin wrapper —
  `{format, appVersion, kind, exportedAt, envelope}` — around the stored
  envelope, so an encrypted export is a file-write rather than a crypto
  operation and works while the library is locked. `validateEnvelope()` was
  lifted out of `readEnvelope()` in `Model/persistence.js` so the importer and
  the loader share one shape check; it now also rejects a `schemaVersion` newer
  than this build, which surfaces as the new `storage.tooNew` banner. Import
  replaces the library, zeroes the keys, logs out and lands on unlock. The code
  splits three ways: `Model/backup.js` (format), `Controller/Universal/backup.js`
  (blobs, downloads, file reads, dialogs) and `View/Universal/backup.js` (one
  block, rendered in both places). Two decisions taken during the build:
  - The block sits on the **welcome page as well as Profile**. Restoring matters
    most exactly when you cannot log in — a corrupt library, a lost password —
    and the `storage.corrupt` banner had been promising a restore since task C.
    Logged out, only import shows unless a valid library is already stored.
  - **Plaintext backups export but do not import.** Restoring one would mean
    validating every field of an untrusted library and re-encrypting it with the
    live key. The readable file is for reading elsewhere, and `parseBackup()`
    says so instead of failing as "unreadable".
- **N — cross-tab safety.** `Controller/Universal/storageSync.js` listens for
  `storage` on `window`. The event only fires in *other* documents, so every
  event is another tab reporting a write. On `spindle:v1:prefs` it calls
  `invalidatePrefsCache()` (the in-memory mirror in `Model/prefs.js` would
  otherwise win), re-applies theme and language and re-renders. On
  `spindle:v1:state` it sets `model.app.libraryStale` — but only while unlocked;
  logged out there is nothing in memory to go stale, and the tab just re-renders
  so the welcome page's "log in" versus "create library" hint stays honest.
  `actuallyPersist()` returns early on a stale library, both before and after the
  encrypt step, so an in-flight save cannot land either. A `null` event key
  (`localStorage.clear()`) is treated as both keys changing. The banner says to
  reload; nothing tries to merge two divergent libraries.

- **O — unknown-route view.** The minimal reading, as decided: `changePage()`
  validates its argument against `model.app.allPages` and falls back to
  `"notFound"` with a `console.warn`, and the `if`/`else` chain in `updateView()`
  ends with `notFoundPage()` rather than an `else if` — so a page added to
  `allPages` but never wired renders the not-found view instead of an empty
  content area. `syncChrome()` treats `notFound` conditionally: chrome stays
  hidden in the logged-out flow and visible inside the app, where the navbar is
  the way out. The view offers the right exit for each case — the library when
  unlocked, the welcome page when not. Hash routing stays deferred to v0.2.

- **Target sizes — app-wide.** Every interactive control in Spindle now meets
  WCAG 2.5.5 (Enhanced, AAA) at 44x44 CSS px, roughly a fingertip. The first
  pass covered only the NO/EN options (36x26), the theme toggle (42x33) and the
  welcome backup `<summary>` (18px tall, below even the 24x24 AA floor). A
  measured sweep of all twelve pages then found 47 more controls under 44 —
  among them `.btn` at 34-39px tall, which alone appears in dialogs, forms,
  album actions and the backup blocks.

  What changed, all of it in `CSS/style.css` except one class name: `.btn`, the
  navbar wordmark and every navbar button, the navbar search field, the mobile
  dropdown items, `.link-btn`, `.form-input`, the `.checkbox-option` and
  `.checkbox-row` labels, both file pickers and their `::file-selector-button`,
  and the unclassed chip buttons — the `+` and `x` toggles in the checkbox group
  and the confirm button in the nested chip form. The navbar absorbed all of it
  without growing: its height is still 56px with every child 44px and centred.

  Two rules worth keeping. A pseudo-element hit area — the usual way to grow a
  target without growing the control — is not available for a segmented pair
  like NO/EN: the two areas would overlap and part of the visible NO button
  would activate EN. And a checkbox is not the target; the `<label>` wrapping it
  is, which is why the fix sits on `.checkbox-option` rather than on the input.

  Four links are deliberately left under 44 and are conformant: the two
  `.about-link`s and the "create library" / "log in" links sit inside a run of
  text, which is exactly the inline exception 2.5.5 carves out. The "back to
  start" link is alone in its paragraph, so the exception does not cover it —
  it got an `.auth-back` class and a real 44x44 box.

  Verified by measuring `getBoundingClientRect()` on every visible control
  across all twelve pages at 375, 768 and 1280 px in both languages, with the
  mobile menu open and the chip forms revealed: 193 controls at 375, 185 above
  it, nothing under 44 but the four inline links, and no horizontal overflow.
  No human pointer touched the screens.

## Conventions

Things that will bite whoever picks this up.

**Architecture.** Model holds state and data — no DOM, no timers. View renders
HTML from state. Controller handles behaviour and wires the two together.

**Rendering.** `updateView()` rebuilds `#app` wholesale from template-literal
functions. There is no per-node binding, which is why a language switch is just
"store the choice and re-render". Anything that must survive a re-render lives
in the model, not the DOM.

**Strings.** Every user-facing string is a key in `Model/i18n/no.js` and
`Model/i18n/en.js`, resolved by `t(key, params)`. The two tables must stay at
parity.

- Store message **keys** on the model, never finished text. `errors.password`
  holds `"error.wrongPassword"`, and the view calls `t()` on it at render time.
  This is what lets a visible error follow a mid-form language switch instead of
  freezing in the language it was raised in. `t("")` returns `""`, so
  empty-versus-set checks keep working unchanged.
- `t()` returns developer-authored text and may contain markup — the `about.*`
  strings carry their own `<a>` tags. User input never passes through `t()`; it
  goes in as a `{param}` and is escaped by the caller.
- English sometimes needs a singular form where Norwegian does not
  ("1 treff" is fine, "1 results" is not). Add a second key for the one string
  that needs it rather than a plural-rule engine.

**Static chrome.** The navbar and footer live outside `#app` and are never
re-rendered. `applyStaticText()` pushes the current language into them and is
called at the end of `updateView()`. Anything added to the chrome in
`index.html` needs an id and a line there, or it stays Norwegian forever.

**Preferences.** `spindle:v1:prefs` is plaintext and holds display preferences
only — language and theme. Nothing sensitive goes in it. It cannot live in the
encrypted envelope because these values are needed *before* there is a key to
open that envelope with. Values are whitelisted on read so a hand-edited blob
cannot put the UI into a state it has no rendering for.

**Seed data is user data.** Starter genres and locations are written in whatever
language is active when the library is created, and then belong to the user. A
later language switch must never rewrite them. The same rule applies to a
restored backup: it carries its own seed lists, and import replaces the
library wholesale rather than merging into the live one.

**Theme.** A script in `<head>` applies the stored theme before first paint,
deliberately duplicating the `spindle:v1:prefs` key literal because
`Model/prefs.js` has not loaded yet at that point. Keep the two in sync.
*(v0.2: it moved out of an inline block into
`View/Universal/themePreload.js` — see `v0.2-plan.md`. Still synchronous and
still in `<head>`; that part is load-bearing.)*

**Boot order.** Scripts are plain `<script>` tags with no modules, so load order
is the dependency graph. The first `updateView()` runs last, after every view
and controller has loaded. *(v0.2: that block is now
`Controller/Universal/boot.js`, loaded from the final `<script>` tag.)*

**Tooling.** There is deliberately no `biome.json` — adding one triggers the
global format hook and reformats all 25 files. Deferred to v0.2 with the Vite
migration.

**Commits.** No `Co-Authored-By` trailer and no tool attribution. Collaborators
are credited in the README and the About page, never in commit metadata.
