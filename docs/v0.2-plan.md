# Spindle v0.2 — plan

Spec of record for v0.2, same as `v0.1-plan.md` was for v0.1. v0.1.0 is
released; everything below is what comes after it.

The theme of v0.2 is that Spindle stops being a folder of scripts and becomes a
built, deployable app — without giving up the thing that makes it Spindle: the
library never leaves the device.

## Shipped

### 1 — every action goes through `data-action`

70 inline `on*` attributes across 13 files are gone. The View no longer carries
behaviour, which is the MVC rule the rest of the app already followed.

- **`View/Universal/bindActions.js`** — one delegated listener per event type,
  bound to `document`. `updateView()` replaces `#app` wholesale, so a listener
  bound to rendered markup would be thrown away with it; delegation also means
  freshly rendered markup is live immediately and nothing is ever re-bound.
- **`Controller/Universal/actions.js`** — `ACTIONS`, the map of 38 named
  handlers, wired once by `initActions()`.

Attribute per event type, so one element cannot answer to two:

| Attribute | Event |
|---|---|
| `data-action` | `click` |
| `data-action-input` | `input` |
| `data-action-change` | `change` |
| `data-action-submit` | `submit` |
| `data-action-toggle` | `toggle` |

Arguments ride as `data-*` attributes beside the name (`data-page`, `data-id`,
`data-index`, `data-panel`, `data-lang`, `data-edit`). The two that reach
further into the app are whitelisted where they land — `changePage()` against
`model.app.allPages`, `setLang()` against `LANGUAGES` — and `data-panel` goes
through the `FORM_PANELS` lookup rather than indexing the model by a string
taken from markup.

Two things fell out of the move. `closest()` stops at the nearest element
carrying the attribute, so a button inside a clickable card answers for itself
and the card never hears about it — that is what the album card's
`event.stopPropagation()` calls were hand-rolling. And an action name with no
handler now warns on the console instead of being a button that silently does
nothing.

### 1b — semantics, and then the CSP

Three clickable things were not keyboard-reachable, and two "links" were not
links. All five are fixed:

- **Brand.** `<h1 onclick>` → `<h1><button class="brand-btn"></h1>`. Note the
  rule is `.Navbar .brand-btn`, not `.brand-btn`: `.Navbar button` is (0,1,1)
  and outranks a single class, so the plain selector silently lost the cascade.
- **Album card.** The card holds two buttons, so it cannot be one. The title is
  now the real control and `.album-open::after` is stretched over the whole card
  — one tab stop named after the album, with the entire card as its pointer
  target, and `.album-actions` raised back above the overlay. This is the same
  pseudo-element trick that does *not* work for segmented controls: there,
  adjacent expanded areas overlap and steal each other's clicks; here each
  overlay is bounded by its own card.
- **Profile card.** No nested buttons, so the whole tile simply *is* the button.
  Innards became spans, because `<button>` only takes phrasing content — the
  stylesheet gives them back `display: block` or the ellipsis truncation stops
  working.
- **Auth "links".** `<a href="#">` → `<button class="link-inline">` and
  `<button class="auth-back">`. They move between pages of a single-page app;
  there was never a URL to follow, and the `href="#"` only ever pushed a stray
  fragment onto the address bar.

With no inline handlers left, the two inline `<script>` blocks were the last
thing standing between Spindle and a real Content-Security-Policy. Both are now
files — `themePreload.js` (still synchronous in `<head>`, still
duplicating the prefs key on purpose, so there is still no theme flash) and
`Controller/Universal/theme.js` + `Controller/Universal/boot.js`. That buys a
`script-src` of plain `'self'` with **no hashes to keep in sync**, which is the
whole reason for preferring a file over an inline script plus `'sha256-…'`.

The policy now ships as a `<meta http-equiv>` in `index.html`. It is enforced:
an injected `<script>` and an external `https://` script are both blocked.

```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
img-src 'self' data:; font-src 'self'; connect-src 'none';
object-src 'none'; base-uri 'none'; form-action 'none'
```

`style-src` still needs `'unsafe-inline'` for the eleven `style=""` attributes
that carry render-time values (the storage bar's width, the chip panels'
visibility). Injected CSS is a far smaller prize than injected script; removing
them is its own job and not a blocker.

### 2 — Vite, Biome, and ES modules

Three commits, in the order the plan called for.

**`biome.json` and the reformat, alone in one commit.** Tabs, LF, final
newline, width 100 — the same rules `.editorconfig` already stated. Only JS,
CSS and JSON are in scope: Biome's HTML formatter is still experimental, and
`index.html` was not worth handing to a beta. `package-lock.json` is excluded,
because npm rewrites it with its own formatting on every install.

Two recommended lint rules are off, both for reasons that expire:

- `correctness/noUnusedVariables` flagged 91 top-level functions, which is what
  "every function is a global" looks like to a linter. **Now that the modules
  have landed, this rule can be turned back on** — it will find real dead code.
- `suspicious/noDuplicateProperties` flagged the deliberate
  `min-height: 100vh` → `100dvh` fallback pair. It cannot tell a
  progressive-enhancement fallback from a mistake, so it stays off.

Left alone deliberately, as behaviour rather than formatting: 13 `==`
comparisons, 7 `!important` declarations, 5 optional-chain suggestions, one
`parseInt` without a radix.

`.gitattributes` also gained `eol=lf` on checkout. The index was already LF,
but `core.autocrlf` handed CRLF back to the working tree, so every formatter
run rewrote endings git then reported as clean.

**Vite, with all 41 `<script src>` tags untouched.** A no-op in the browser, as
predicted. The CSP needed less relaxing than feared: only the HMR websocket is
blocked, by `connect-src 'none'`, because Vite's dev client is a real file and
`script-src 'self'` already covers it. So `vite.config.js` rewrites that one
directive while serving, instead of stripping the whole meta tag — the rest of
the policy stays enforced in development. `npm run build` did not produce a
working app at this commit, and was not made to: Vite refuses to bundle a plain
`<script src>` without `type="module"` and drops it, which is exactly what the
module conversion fixes.

**ES modules.** 41 script tags collapsed to one:
`<script type="module" src="Controller/Universal/boot.js">`. Every file exports
only what another module actually reads, and imports what it uses; `boot.js`
imports `storageSync.js` for its side effect alone, since that module registers
the cross-tab `storage` listener and exports nothing. `navbar&Mobile.js` became
`navbarMobile.js` before the `&` could become an import specifier.

`themePreload.js` moved to `public/themePreload.js` and is loaded as
`/themePreload.js`. It is the one file Vite must not touch: `public/` is copied
to the output verbatim, and anything Vite bundles becomes a module — deferred by
definition, which is the theme flash all over again. The rest of the app is a
module graph; that file deliberately is not part of it.

**What the conversion made visible.** Ten View files import from Controller,
and `Model/i18n/i18n.js` imports `updateView` from View. Under `<script>` tags
these were invisible global calls; as imports they are edges in a graph, and
they point the wrong way for MVC. Nothing was refactored to fix that here — the
commit would have stopped being a mechanical conversion — but the list is short
and worth its own pass.

**Verified**, dev and built output both: register creates the seeded library,
save adds an album, validation blocks an incomplete one, login decrypts after a
reload, encrypted export downloads, language and theme switch and survive a
reload. The built bundle still blocks an injected inline script, so the CSP
survived the move. The confirm-dialog flows cannot be finished in this preview
pane — `<dialog>`'s `close` event never fires without compositing — so deletion
was confirmed only as far as the dialog opening.

### Also fixed on the way past

The navbar overflowed a 375px viewport by 4px in English **before** any of this
work — the theme toggle was pushed off the right edge, and the v0.1 "zero
horizontal overflow" check missed it because the preview pane reports a 0×0
viewport unless the tab is explicitly resized. Root cause was flexbox: a flex
item defaults to `min-width: auto` and refuses to shrink below its content, so
a longer label pushed the row wider instead of narrowing the search box.
`.nav-mobile` and `.Navbar input` now carry `min-width: 0`, and the navbar's
mobile side padding dropped from `1.5rem` to `0.75rem` (restored at 768px).

Verified at 375 / 768 / 1280 in both languages: zero horizontal overflow, every
target ≥ 44×44 except the two documented exceptions (a bare checkbox — the
wrapping `<label>` is the target — and inline links inside a run of text).

## 3 — Hash routing

Pages become linkable and the back button works. Touches every `changePage()`
call site, which is why it waited for the module conversion — that has now
landed, so this is next. `changePage()` already validates against `model.app.allPages` and
falls back to the not-found view, so the router has a landing place for a
garbage fragment on day one.

Note that the auth links no longer write `#` to the URL (see 1b), so the
fragment is now free for the router to own.

## 4 — Deploy + security headers

**Cloudflare Pages, not GitHub Pages.** GitHub Pages cannot set response headers
at all, which is why the policy currently lives in a `<meta>` tag —
and `frame-ancestors` cannot be expressed there, so clickjacking protection is
simply missing until this lands. Cloudflare Pages sets real headers via
`_headers`, and it is coherent with the Cloudflare Registrar plan for
`malinfossum.dev`.

Starting point for `_headers` — the same policy plus the parts a `<meta>` tag
cannot carry:

```
/*
  Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
  Referrer-Policy: no-referrer
  X-Content-Type-Options: nosniff
  Permissions-Policy: camera=(), microphone=(), geolocation=(), interest-cohort=()
  Cross-Origin-Opener-Policy: same-origin
```

Remove the `<meta>` tag once the header is live so there is one policy, not two
that can drift.

**No database, by design.** `localStorage` plus client-side AES-GCM is the
security model, not a stepping stone to a backend. Adding a server database
would break the property the app is built around.

## 5 — Plaintext import

Still deferred, and the honest assessment is that it should be dropped. It means
validating an untrusted library field by field — the highest-risk surface in the
app — for the lowest user value, given that encrypted import already covers
"move my library to a new browser".

## Conventions added in v0.2

These join the `v0.1-plan.md` conventions, which all still hold except the two
noted below.

**Actions.** No inline `on*` attributes, ever. A new interactive element gets a
`data-action*` attribute and an entry in `ACTIONS`. Arguments go in `data-*`
attributes, never interpolated into executable strings. Anything from an
attribute that indexes into the model goes through a lookup, not a bare key.

**No inline scripts.** This supersedes the v0.1 "Theme" and "Boot order"
conventions, which described both as inline blocks in `index.html`. They are
`public/themePreload.js` and `Controller/Universal/boot.js` now. An
inline script would force `'unsafe-inline'` and undo the CSP.

**Semantics.** Actions are `<button>`, navigation is `<a>`. A clickable `<div>`
is a bug. Where a whole card must be clickable but contains its own buttons, use
the stretched-`::after` pattern on the card's primary control — never
`role="button"` plus `tabindex`.

**Modules.** One entry point, `Controller/Universal/boot.js`. A file exports
only what another module reads; anything else stays private. `public/` is for
the files Vite must not transform, and today that is exactly one —
`themePreload.js`, which has to stay a classic synchronous script.

**Verifying layout.** The preview pane reports a 0×0 viewport by default, which
makes every geometry measurement meaningless — including target sizes and
overflow. Set the viewport explicitly before measuring, and check 375 / 768 /
1280 in both languages.
