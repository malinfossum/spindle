# Spindle v0.6 — plan

Spec of record for v0.6. v0.5 is closed: Scan looks up on its own, the cover
arrives from the barcode, and "Stay unlocked on this device" survives Android
discarding the tab. The phone pass ran 2026-09-22/23 and passed.

v0.6 gives Spindle a face and makes it installable. Today it has no favicon, no
app icon, no manifest, no link preview and no service worker — and
`package.json` calls it "a private, offline music library" while the app cannot
open without a network. After v0.6 that sentence is true.

**Status:** designed 2026-09-24, not built. Stress-tested the same day
(security, privacy, accessibility, loopholes); its ten fixes are folded into
§§ 1–4 below. Next step: the task breakdown.

**All decisions are made (2026-09-24).** They were taken visually, side by side,
and are in § 0.

---

## 0 — Decisions

| # | Question | Decision |
|---|---|---|
| 1 | What does "installable" deliver? | **Install and open offline.** The service worker caches the app itself and nothing else. The library is already on the device; now the app is too. Look-ups still need a network and say so. |
| 2 | What is the mark? | **A record, fitted to the edge:** lighter vinyl with a visible sheen and grooves, the **gold label from the welcome page** (`#d4af37`, rim `#b8962e`) and the spindle hole. The same record as the welcome page, so the app has one picture of itself. |
| 3 | No black corners anywhere. How? | **Two variants of one drawing** (my standard for every project from now on): an **`any`** icon with a transparent background — no plate, so no corners — and an opaque **`maskable`** icon with the record inside the safe zone on a plate. Never `"any maskable"` on one entry. |
| 4 | What colour is the maskable plate? | **Accent blue, `#4a80d4`.** Brightest on a dark home screen, and blue against gold is the strongest pair of the three I compared (light `#eef1f6` and navy `#1e3050` were the others). |
| 5 | When a new version deploys? | **Quietly, on the next launch.** No reload under me: a reload clears a half-filled form and locks the library when "Stay unlocked" is off. A fix arrives one launch later; that is the price. An immediate takeover was never an option — it mixes old pages with new files. |
| 6 | Own Install button? | **Yes, a row in Profile**, shown only where the browser supports it, gone once installed. On iOS Safari the row is the instruction instead: Share → Add to Home Screen. Capturing the event also retires Chrome's automatic install banner, so installing happens when I choose it. |
| 7 | Link preview image? | **The welcome page's composition on dark:** "Spindle" and the tagline on the left, a large record running off the right edge. English. |
| 8 | How is it built? | **A hand-written service worker plus a small Vite plugin**, not `vite-plugin-pwa`/Workbox — the build is one HTML, one JS and one CSS file, and four files do not need a framework. Icons are rendered from SVG masters by a script using **`sharp`**, the one new dev dependency; it never ships to the browser. The PWABuilder generator was rejected: it pads the image its own way, which fights the maskable plate, and its output cannot be rebuilt from the repo. |

The `domain/app-icons` rule behind #3 comes from MDN (*Define app icons*,
manifest `icons`), web.dev (*Maskable icons*, *Learn PWA: app design*) and
Microsoft (*Edge: icon and theme colour*, *Windows app icon design and
construction*).

## 1 — The mark and the icon set

### Masters (drawn by hand, in `public/icons/`)

- **`icon.svg`** — `any`. The record alone on a transparent 512 grid, outer
  radius 254. Vinyl is a radial gradient (`#6a6a6a` → `#2e2e2e` → `#0e0e0e`,
  centre at 36 % / 30 %), four grooves in white at 9–13 % alpha, the gold label
  at radius 104 with its rim, a faint inner ring and the hole.
- **`icon-maskable.svg`** — the same record scaled to fit inside the safe zone
  (a centred circle, radius 40 % of the width = 204.8 on 512), on a full
  `#4a80d4` square. Every mask — circle, squircle, rounded square — shows the
  whole record with plate around it.
- **`icon-small.svg`** — for 16 and 32 px: no grooves and no sheen, just the
  vinyl disc, the gold label and the hole, so the rings do not merge into mud.
  Drawn and checked at real size before it is committed.
- **`og-image.svg`** — 1200 × 630, `#111111`, "Spindle" at 700 and the tagline
  in `#9a9a9a` on the left, the `any` record at ~550 px running off the right.

### Generated (by `npm run icons`, committed)

`scripts/icons.js` renders with `sharp` and packs the `.ico` itself (PNG
entries inside an ICO header — a few lines, no second dependency).

| File | From | Size | Used by |
|---|---|---|---|
| `icons/icon-192.png`, `icons/icon-512.png` | `icon.svg` | 192, 512 | manifest `any` |
| `icons/icon-maskable-192.png`, `icons/icon-maskable-512.png` | `icon-maskable.svg` | 192, 512 | manifest `maskable` |
| `apple-touch-icon.png` | `icon-maskable.svg` | 180 | iOS home screen (opaque — iOS fills transparency with black) |
| `favicon.ico` | `icon-small.svg` ×2, `icon.svg` | 16, 32, 48 | browsers asking for `/favicon.ico` |
| `og-image.png` | `og-image.svg` | 1200 × 630 | link previews |

The generated files are committed so a deploy never depends on the script.

### Manifest (`public/manifest.webmanifest`)

```json
{
  "id": "/",
  "name": "Spindle",
  "short_name": "Spindle",
  "description": "A private, offline music library that never leaves your device.",
  "start_url": "/",
  "scope": "/",
  "display": "standalone",
  "background_color": "#111111",
  "theme_color": "#141414",
  "icons": [
    { "src": "/icons/icon.svg", "sizes": "any", "type": "image/svg+xml", "purpose": "any" },
    { "src": "/icons/icon-192.png", "sizes": "192x192", "type": "image/png", "purpose": "any" },
    { "src": "/icons/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any" },
    { "src": "/icons/icon-maskable-192.png", "sizes": "192x192", "type": "image/png", "purpose": "maskable" },
    { "src": "/icons/icon-maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ]
}
```

`id` is set explicitly. Without it the app's identity is `start_url`, and
changing that later (to `/#library`, say) would make browsers treat Spindle as
a different app and strand every existing install.

### `<head>` in `index.html`

- `<meta name="theme-color" content="#141414">` — **above**
  `<script src="/themePreload.js">`, because the preload rewrites it before
  first paint and a script cannot find an element the parser has not reached.
- `<meta name="description">` with the tagline.
- `<link rel="icon" href="/favicon.ico" sizes="48x48">` and
  `<link rel="icon" href="/icons/icon.svg" type="image/svg+xml">`.
- `<link rel="apple-touch-icon" href="/apple-touch-icon.png">`.
- `<link rel="manifest" href="/manifest.webmanifest">`.
- `og:type`, `og:title`, `og:description`, `og:url`, `og:image` (absolute:
  `https://spindle-music.pages.dev/og-image.png`), `og:image:width`/`height`,
  `og:image:alt`, and `twitter:card` = `summary_large_image`.

### `theme-color` follows the app's theme

The app's theme is my choice in Profile, not the OS setting, so the meta tag
follows `data-theme`, not `prefers-color-scheme`: `#141414` on dark and
`#ffffff` on light — the navbar's colour, so the address bar and the installed
window's title bar continue it. `themePreload.js` sets it before first paint;
`applyTheme()` in `Controller/Universal/theme.js` updates it on every switch.

## 2 — The service worker

### Source and build

`sw.js` lives at the repo root next to `index.html` and carries two
placeholders: the file list and the version. A plugin in `vite.config.js`
(`generateBundle`) collects every emitted file name plus the files copied from
`public/` that the app needs (not `_headers`, not `og-image.png`), fills the
placeholders, and emits `dist/sw.js`. `index.html` enters the list as `/` —
see *The `/index.html` redirect* below.

The version is a hash of the **contents** of every listed file plus the
contents of `public/_headers`, not of the names. Only Vite's bundled files carry
content hashes; `themePreload.js`, the manifest, the icons and `favicon.ico`
keep their names when they change, and a name-only version would leave
`sw.js` byte-identical and the old file cached for good. `_headers` is in the
hash because Cache Storage keeps a response's headers: the cached `/` carries
the CSP it was fetched with, so a policy change must be a new worker too. The
list-and-version function is pure and exported so `node --test` can check it,
including that a changed file under an unchanged name changes the version.

Registration is in `Controller/Universal/boot.js`, production builds only
(`import.meta.env.PROD`). The dev server never sees a worker, so HMR is
untouched; `npm run build && npm run preview` is how it is tested locally.

### Behaviour

- **install** — open `spindle-<version>`, then fetch each entry in the list
  itself rather than `addAll`: any entry other than `/` that comes back
  `redirected` or as `text/html`, or any entry that is not `ok`, rejects the
  install, and the old worker keeps running. Everything else is `put` in the
  cache. No `skipWaiting`.
- **activate** — delete every `spindle-*` cache that is not the current one.
- **fetch** — only same-origin `GET` is handled. A navigation answers with
  `caches.match("/")` (routing is fragment-based, so every page is that one
  document); anything else answers from the cache, falling back to the
  network. Nothing fetched at runtime is added to the cache.

### The `/index.html` redirect

Cloudflare Pages answers `/index.html` with a **308 to `/`**. `addAll` would
follow it and store a response flagged `redirected`, and a browser refuses a
redirected response as the answer to a navigation — so every launch the worker
controls would fail, online as well as offline. The document is therefore
cached, and matched, as `/`. `npm run preview` does not redirect, which is why
§ 4 step 3 runs on a Cloudflare preview.

### Pages' HTML fallback

There is no `404.html`, so Pages answers any missing path with `index.html`
and a **200**. `addAll` could never fail on a wrong name in the list — it
would cache the page under an icon's or a script's name, and the app would
break offline only. That is why install checks the type of every entry
instead of trusting the status.
- **Cross-origin requests are never intercepted.** MusicBrainz, the Cover Art
  Archive and archive.org go straight to the network under the page's own CSP,
  exactly as today.

### What it never touches

The worker has no access to `localStorage`, never opens IndexedDB, and caches
only files that are public on the deployed site anyway. The library, the
covers and the key never enter Cache Storage.

### Quiet update

The browser checks `sw.js` on navigation — and with fragment routing there is
no navigation after launch, so the page also calls `registration.update()`
whenever it becomes visible again (`visibilitychange`). That is one small
request; it never reloads anything. A changed worker installs in the
background and waits; when every Spindle window is closed it activates, the
old cache is deleted, and the next launch runs the new version. No banner, no
reload.

"Closed" means closed: on Android, an installed Spindle left in the recent
apps list keeps its window, and the new version waits until it is swiped away.

### Rollback

If a worker ever ships broken, the way out is a replacement `sw.js` that
calls `skipWaiting()`, deletes every `spindle-*` cache and unregisters itself.
The browser fetches `sw.js` past the HTTP cache, so the next check finds it.
Written down here, not built.

### The CSP change

`connect-src` gains `'self'`. A worker runs under the CSP of its own script
response — the same `/*` rule in `public/_headers` as every other file — and
precaching is a same-origin fetch that the current four-host list blocks.

Considered instead: a looser policy for `/sw.js` alone. Cloudflare Pages joins
two values of the same header with a comma, which enforces both policies, and
removing a header and setting it again in one rule is not documented. `'self'`
lets nothing leave the device. The dev-server string replace in
`vite.config.js` must still match the new line; it throws when it does not.

## 3 — The Install row

`Controller/Universal/install.js` listens for `beforeinstallprompt`, calls
`preventDefault()` and keeps the event; `appinstalled` drops it. Profile
renders one row, in the Log out row's shape (label + 44 px button):

| Situation | Row |
|---|---|
| Event kept, not installed | "Install Spindle" + **Install** button → `prompt()` |
| Prompt answered | A sentence in `role="status"` in place of the button (below) |
| iOS Safari, not standalone | The instruction, as a sentence (below) |
| Running installed (`display-mode: standalone`) | Nothing |
| Any other browser (e.g. Firefox desktop) | Nothing |

The choice between those five is one pure function with its own tests.

**One event, one press.** `prompt()` can be called once per event, so the
event is dropped the moment Install is pressed, whatever the answer — a second
press can never reach a spent event. `beforeinstallprompt` often arrives
seconds after load, or later, so when it arrives or leaves while Profile is on
screen, the row alone re-renders; it does not wait for the next full render.

**Focus and outcome.** Pressing Install removes the button, so focus must not
fall to `<body>`. When `prompt()` resolves, the row shows one sentence in
`role="status"`, and that line takes focus (`tabindex="-1"`):

- accepted — "Spindle is installed — open it from your home screen."
- dismissed — "Not installed. The browser menu can still install it."

**The iOS instruction** is a sentence, not an arrow chain (a screen reader
reads "→" as "right arrow"), and it names Apple's own menu labels in each
language: *Del*, then *Legg til på Hjem-skjerm* in Norwegian; *Share*, then
*Add to Home Screen* in English. The Norwegian labels are unverified — I have no
iPhone (§ 5).

New keys in `Model/i18n/no.js` and `en.js`, Norwegian first: the row label and
button, the two outcome sentences and the iOS instruction.

## 4 — Verification

1. `npm test` — list/version builder (including a changed file under an
   unchanged name), Install-row rule.
2. `npm run build && npm run preview` in the browser pane, reloaded once (the
   first visit is not controlled — there is no `clients.claim()`): the worker
   controls the page, `caches.keys()` shows one `spindle-*`, the manifest
   parses in the page. **Then stop the preview server and reload: the app must
   open.** That is offline launch, proven locally.
3. **The gate before merging:** the PR's Cloudflare preview URL, because
   preview serves no `_headers`, never redirects `/index.html` and has no HTML
   fallback — none of the three Cloudflare traps in § 2 exist there. After one
   reload: the worker controls the page, one `spindle-*` cache, and every entry
   is `ok`, not `redirected`, with the `content-type` its extension calls for.
4. A second build with one changed file → a new version installs and waits;
   closing and reopening the tab switches to it and the old cache is gone.
5. A look-up with the worker active still reaches MusicBrainz and the cover
   still lands (cross-origin untouched).
6. Every icon at real size, favicon on dark and light tabs, measured — rings
   do not merge at 16 px.
7. Deployed: `curl -I` shows `connect-src` with `'self'`; the manifest and
   icons return 200; maskable.app shows the record whole under every mask.
8. My phone: install from the Profile row on Android, launch in airplane mode,
   check the icon under the launcher's mask.
